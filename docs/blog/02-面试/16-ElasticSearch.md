# ElasticSearch
## 1、分布式实时全文搜索引擎



## 2、什么是倒排索引

倒排索引是一种索引结构，它与传统的正向索引相反。传统的正向索引是从文档到文档内容的映射，

而倒排索引是从单词（或其他索引项）到包含该单词的文档列表的映射。

就是以单词为关键字，记录该单词在哪些文档中出现过以及在文档中的位置等信息。

组成：单词表（根据字典顺序升序排列）、倒排列表

## 3、为什么ES检索比MySQL快

索引结构，MySQL使用B\+树，数据存在磁盘中，查询是需要多次磁盘IO，非覆盖索引需要回表。

ES使用倒排索引，将文档中的分词和文档id映射，快速定位关键词。倒排索引由分词表和文档id列表组成的。

内存中构建term Index（前缀树结构），查询时在内存中快速定位分词在分词表中的位置，减少磁盘访问次数。

分布式架构和并行处理，数据按分片分布到多个节点，查询时并行检索各分片，提升吞吐量

## 4、text 和 keyword类型的区别

keyword不会被分词，直接根据字符串建立倒排索引

text会先分词，然后根据分词内容建立倒排索引

## 5、ES在高并发下如何保证读写一致性

1. 修改操作的时候，用版本号的乐观锁，文档被修改，版本号加1，每次用预期的版本号来修改，如果对不上，就说明被其他修改了，则不改动。

2. 写操作的时候，要求ES中大部分分片是活跃可用的，才执行写操作。

3. 读操作，设置replication 为 sync，使读操作在主分片和副本分片上都完成才可以返回。

## 6、ES索引数据多了怎么办，如何调优

1. 动态索引，基于模板\+时间\+rollover api滚动创建索引，不至于数据量激增导致单个索引数据量非常大

2. 冷热数据分离存储，最近3天或者一周为热数据，其余为冷数据，冷数据不再写入新数据

3. 对于过期或无用的数据，及时进行清理，减少索引大小和查询范围
