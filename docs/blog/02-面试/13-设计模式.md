# 设计模式
## 1、创建型模式

### 1、单例模式

保证一个类仅有一个实例，并提供一个全局访问点。

就像 Windows 系统中的任务管理器，无论在系统的任何地方调用它，都是同一个实例。

### 2、工厂模式

定义一个创建对象的接口，让子类决定实例化哪个类。

ioc容器在创建bean的时候使用了工厂模式

### 3、抽象工厂模式

提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们具体的类。例如，在一个跨平台的 UI 框架中，使用抽象工厂模式可以根据不同的操作系统，创建出相应平台风格的按钮、文本框等 UI 组件。

### 4、建造者模式

将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。stringBuilder是由建造者模式构建的

### 5、原型模式

用原型实例指定创建对象的种类，并且通过拷贝这些原型来创建新的对象。在Java中就是克隆，实现Cloneable接口，分为浅克隆和深克隆

## 2、结构型模式

### 1、代理模式

为其他对象提供一种代理以控制对这个对象的访问。可以前后加逻辑增强方法的功能

AOP、日志记录、事务管理使用代理模式

### 2、装饰器模式

动态地给一个对象添加一些额外的职责。就像给手机添加保护壳、贴膜等配件，

这些配件可以在不改变手机本身功能的基础上，为手机增加一些额外的功能或保护。

### 3、适配器模式

将一个类的接口转换成客户希望的另一个接口。例如，在电脑上使用 USB 接口的打印机时，

需要一个 USB 转接口来将打印机的接口转换成电脑能够识别的 USB 接口，这个转接口就相当于适配器。

## 3、行为型模式

### 1、观察者模式

定义了一种一对多的依赖关系，让多个观察者对象同时监听某一个主题对象。

spring的事件监听机制、消息队列等使用

### 2、策略模式

定义了一系列的算法，将每个算法都封装起来，并且使它们之间可以互换。

lua包的加密算法，如sha256、rsa、md5、AES等，根据前台配置，调用不同的算法，得到密文。

### 3、责任链模式

使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。

将这些对象连成一条链，并沿着这条链传递该请求，直到有一个对象处理它为止。

如在公司的请假审批流程中，请假申请可能会依次经过组长、经理、总监等多个审批环节。

## 4、单例模式创建方法

1. 饿汉式：类初始化的时候，就立即加载该对象，线程安全

2. 懒汉式：类初始化的时候，不会加载该对象，等待真正需要的时候才会加载该对象，使用双重检测锁机制

3. 双重检测锁机制：使用Volatile和Synchronized，Volatile具有可见性，并且可以阻止指令重排

4. 指令重排
