# JVM
## 1、JVM内存模型

### 1、运行时数据区域

（1）程序计数器（私有），当前线程执行字节码的行号指示器。

（2）Java虚拟机栈（私有），存储局部变量表，操作数栈，动态连接，方法出口等信息。

（3）本地方法栈（私有），和Java虚拟机栈类似，不过它是为虚拟机使用到的本地方法服务的。

（4）Java堆（共享），是所有线程共享的运行时内存区域，几乎所有的对象实例和数组都在堆上分配内存。

（5）方法区（共享），jdk1\.8之后移除了，使用以元空间实现方法区的功能，元空间使用本地内存，避免方法区内存溢出

### 2、本地内存

元空间、直接内存

### 3、运行时常量池

是方法区（元空间）的一部分，存放常量

### 4、Java堆

作用：存储对象实例，垃圾回收的主要区域。

结构划分：

新生代，对象刚创建时存放区域，大多数对象在新生代中产生和消亡

老年代，用于存放经过多次垃圾回收后仍然存活的对象。

永生代（jdk1\.8后替换为元空间）

## 2、哪些区域可能OOM

1、Java堆：对象持续创建，且 GC 无法回收（如内存泄漏）；堆大小设置过小（\-Xmx 太小）

## 5、垃圾收集算法

1. 标记\-清除算法，标记已经死亡的对象，清楚掉

2. 标记\-整理算法，将存活的对象像一端整理，在边界处将其他的删除

3. 标记\-复制算法，将存活的对象复制到另一半，然后删除其他的

4. 分代算法，一般新生代死亡对象比较多，用标记\-复制算法，老年代死亡比较少，用标记\-清理算法。

## 8、双亲委派加载模型

每一个类都有一个对应它的类加载器。系统中的ClassLoder 在协同工作的时候会默认使用 双亲委派模型 。

即在类加载的时候，系统会首先判断当前类是否被加载过。已经被加载的类会直接返回，否则才会尝试加载。

保证Java程序稳定运行，类不会被重复加载

## 9、堆栈的区别

1. 堆内存在分配时是不连续的，栈是先进先出，是连续的

2. 堆分配的内存是在运行期确认的，因此大小不固定，栈是在编译期确认的，大小固定。

3. 堆存放的是对象的实例和数组，栈存放是局部变量，操作栈数，方法出口等。

4. 栈比较小，一般是线程私有的，堆比较大，是所有线程共享的

## 10、jvm调优\-参数设置

- \-Xms：初始化堆大小，一般设置为2g

- \-Xmx：堆最大内存，一般设置为2g

- \-Xmn2g：设置新生代大小

- \-XX:NewRatio=4，\-XX:SurvivorRatio=8：设置新生代和老年代比例

- \-Xss128k：设置线程大小

- \-XX:\+UseG1GC \-XX:MaxGCPauseMillis=50：设置GC算法

- \-XX:MaxMetaspaceSize=2g：设置Meta区内存大小

- \-XX:\+HeapDumpOnOutOfMemoryError \-XX:HeapDumpPath=/usr/local/：设置堆内存溢出时打印dump文件

- \-Dsun\.net\.client\.defaultConnectTimeout=2000：设置连接超时时间

## 12、Java中的对象一定是在堆上分配的吗？

不一定，如果满足逃逸分析条件的话，一个对象可以在栈上分配

## 13、OOM后，JVM一定会退出吗？为什么？也就是程序会挂吗？

不一定，线程调用发现堆内存空间不足，抛出OOM异常，线程具有独立性，不会抛给其他线程，

线程拿到异常，有两种处理方式：捕获异常自己处理，线程继续执行，线程停止执行。

jvm退出条件是不存在非守护线程（前台线程），jvm就会退出。所有OOM和jvm退出没有很强的关系

如果是所有发非守护线程申请内存不足OOM，jvm会退出

或者OOM后，操作系统内存也耗尽了，Linux会找出占用最多进程并杀死，jvm会被动退出

## 14、JVM预热是什么

1. 一般情况下，Java服务刚启动的时候，处理的第一个请求的响应速度要比正常情况下的要慢，如果在启动的瞬间，大量的请求访问过来，会导致系统崩溃，所以需要JVM预热

2. 第一次慢的原因：OpenJDK使用的是JIT即使编译技术，动态的将Java代码编译成机器码，提高运行效率；但是在JIT之前，Java代码会被较低效率的解释器模式执行，Java服务启动后，Java方法还没有被JIT编译，大量的请求就过来了；就会导致请求响应慢，最终可能导致服务崩溃。

3. JVM预热，就是在Java服务启动后，不会立即对调用方提供正常流量访问，而是先用较小的流量来调用服务，让服务逐步的达到可以提供正常响应效率，然后再完全开发流量。

4. JVM预热方案：1、使用流量控制来进行预热；可以使用网关的流量控制功能，对于新上线的服务，根据上线时间给与不同的流量访问权重，让服务逐步的承接流量。或者使用sentinel的warm up预热功能，将过高的流量拦截，使服务平稳运行。2、服务启动提供正常访问之前，服务自行进行预热；设置一个初始化模块，在这个模块中编写遍历所有重要接口的代码，服务启动后，就会执行这个模块，对接口预热。
