# 大厂面试题
## 1、小红书扫描登录pc端实现原理

（1）本质：已登录设备向未登录设备传递信任

（2）3个角色：

1. pc端，待登录设备

2. 手机端，可信任设备

3. 服务器，裁判，验证双方身份，传递信任

（3）阶段一：生成二维码

1. pc端向服务器申请二维码，带上自己的设备信息

2. 服务器生成唯一二维码ID

3. 服务器存状态，pc生成二维码。服务器把二维码ID、pc设备信息、过期时间、当前状态（未扫码）存储redis。服务器把二维码ID返回给pc，pc端生成二维码

4. pc端轮询，每3s向服务器发送请求询问二维码是否被扫描，状态是否改变。不用长连接，因为量大的话会占用服务器资源，轮询轻量成本低，过期时间到后就不在轮询。

（4）阶段二：手机扫码

1. 手机解析二维码，获取二维码ID

2. 手机发请求给服务器，内容：二维码ID，手机token（小红书手机端登录后获取的token），手机设备信息（防止token被劫持）

3. 服务器验证手机端的信任度先查redis，确认二维码ID是否存在，是否过期，状态是否未扫码再验证手机token，是否在有效期，是否对应真实用户，token绑定设备信息和扫码设备是否一致

4. 服务器更新状态，手机端弹出确认；服务器更新二维码状态为已扫码、待确认。服务器返回扫码成功给手机，手机弹出确认登录弹框（二次确认，是防止误扫直接授权了）

（5）阶段三：确认登录

1. 手机端点击确认登录后，向服务器发送请求，带上二维码ID、token

2. 服务器最终验证，更新状态；确认token有效期，二维码ID有效期，状态是否待确认；修改redis中状态为已确认、登录成功，同时删除二维码ID（避免重复使用）

3. pc端轮询到结果；pc端第N次轮询后，服务器发现状态变为已确认，就生成一个pc端专用token，绑定pc设备；服务器把pc专用token返回给pc端，pc再用这个token调用用户信息接口获取用户数据，完成登录

4. pc端登录后，会将token保存在本地cookie中，并记录过期时间

（6）异常场景一：二维码过期后处理

1. pc端轮询获取过期信息后，会弹出“二维码过期，请重新生成”，重新走二维码生成流程

2. 为什么过期时间2分钟？时间太短用户来不及拿手机扫码，时间太长增加盗扫风险

（7）异常场景二：扫了其他设备二维码

新设备登录，会判断你的账号是否和这个设备有历史关联，

如果没有，会在手机端有风险提示，并增加其他的验证手段，比如输入密码验证

（8）异常场景三：手机扫码后断网

1. 服务器会保持已扫码、待登录状态，直到过期

2. 手机端恢复后，会重启请求服务器二维码状态，未过期，则继续点击确认，过期，则提示重新扫码

3. pc端持续轮询，直到二维码过期
